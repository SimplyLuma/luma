# Repository instructions

Keep OS, bundled apps and the shared platform in one converged source tree. Device and architecture differences belong in profiles or scoped patches. Creative, Office and standalone Imager are separate products.

Preserve unrelated work, upstream notices and licenses. Never commit credentials, private evidence, user databases or generated images/packages. Run relevant component checks and report actual evidence; do not claim a test passed unless it ran successfully. Do not add a human sign-off on someone else's behalf.

Use README.md, BUILDING.md, CONTRIBUTING.md and SECURITY.md for public workflow guidance. Release publication and signing require their own authorized infrastructure; a source commit does not authorize deployment.

Keep user-facing changelogs brief and factual: name the concrete fix, addition or removal when known. Otherwise use “General bug fixes.” Never substitute mock-up text or claim improvements that were not verified for that release.
