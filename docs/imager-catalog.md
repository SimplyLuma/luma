# Imager catalog

Luma Imager reads one signed document that lists desktop architectures and
channels, add-ons and phones, so a new device appears without an app update.

- URL: `https://media.simplyluma.com/imager/v1/catalog.json` and
  `catalog.json.minisig`.
- Signature: the update-graph minisign key (`config/os/keys/luma-update-graph.pub`),
  trusted comment `luma-imager-catalog schema=1 generated_utc=<generated_utc>`.
- Schema: [`imager/catalog.schema.json`](../imager/catalog.schema.json).
- Generated by `tools/build-imager-catalog.py`; never edited by hand.

Imager rejects a catalog with a bad signature, one larger than 1 MiB, and one
whose `generated_utc` is older than the copy it already has. It ships a copy
as its fallback.

## Format (schema 1)

| Key | Meaning |
|---|---|
| `schema` | `1`. A change that old Imagers cannot read gets a new number and a new `/imager/v<n>/` path. |
| `generated_utc` | When the catalog was built, `YYYY-MM-DDTHH:MM:SSZ`. The only field that changes between two builds of the same sources. |
| `imager.min_version` | Oldest Imager that understands this catalog. |
| `desktop.architectures[]` | `id` (`x86_64`, `aarch64`), `name`, `status`. `aarch64` is `available` only while the nightly index lists an aarch64 image. |
| `desktop.channels[]` | `id`, `name`, `status`, optional `default` (exactly one) and `index_url` (the channel's signed `latest.json`; required when available). |
| `desktop.hub_catalog_url` | Where Imager lists desktop images. Images are not in this catalog. |
| `desktop.guide[]` | `title`, `body` steps for a desktop install. |
| `mods[]` | `id`, `name`, `summary`, `arch[]`, `status`, `kind` (`derived_channel`, `macos_installer`), `note` (string or null), `suggest_when` (object or null; `dmi_sys_vendor`). |
| `phones[]` | `id` (`<vendor>-<codename>`), `vendor`, `codename`, `name`, `summary`, `picture_url`, `tier`, `status`, `method`, `fastboot_product`, `never_write[]`, `needs[]`, `release`, `guide[]`. |
| `phones[].release` | Null when nothing is published; otherwise `name`, `date` and `files[]` with `role` (`boot`, `system`, `sd_image`, `checksums`, `other`), `name`, `url`, `sha256`, `size_bytes`. |

`status` is `available`, `coming_soon` or `unavailable`. Phone `method` is
`fastboot_bundle`, `sd_card` or `none`. Guide steps are ordered; Imager
numbers them. Text is plain sentence case without exclamation marks.

`never_write` lists partitions Imager must never flash, erase or format. It is
the device's `[install].preserve`.

## Sources

| File | Gives |
|---|---|
| `imager/catalog.toml` | `imager`, `desktop`. `status_from_index` names the channel whose index decides an architecture's status. |
| `imager/mods/<id>.toml` | One add-on; the file name is its `id`. |
| `devices/<vendor>/<codename>/device.toml` | A phone, when it has an `[imager]` table: `status`, `method`, `summary`, optional `picture`, `needs`, `[[imager.guide]]`. `name` is `marketing_name` (else `name`); `tier`, `fastboot_product`, `never_write` and the newest `[[releases]]` entry come from the manifest. |
| `imager/phones/<vendor>-<codename>.toml` | An overlay for a device whose directory is on another branch: `vendor`, `codename`, `name`, `tier`, optional `fastboot_product`, `never_write` and an `[imager]` table. If the device's `device.toml` is also present, the overlay's keys win. Delete the overlay once the device's own `[imager]` table reaches this branch. |

Release files map from `[[releases]]`: `boot_image` to `boot`, `system_image`
to `system` (`sd_image` for `sd_card` phones) and `checksums` to `checksums`,
each with its `*_sha256`. The generator reads each file's size with an HTTPS
HEAD request and falls back to `*_size_bytes` in the manifest; a served size
that differs from the manifest fails the build. An `available` phone must
state those sizes, so the catalog also builds offline.

## Adding a phone

1. Add `[imager]` to the device's `device.toml` (or an overlay in
   `imager/phones/` if the device lives on another branch):

   ```toml
   [imager]
   status = "coming_soon"
   method = "fastboot_bundle"
   summary = "One sentence."
   needs = ["A USB-C data cable"]

   [[imager.guide]]
   title = "Unlock the bootloader"
   body = "Short, plain steps."
   ```

2. To make it `available`, publish a `[[releases]]` entry with sha256 and
   `*_size_bytes` for every file, and write the guide. Keep every warning from
   the device's `INSTALL.md` that protects the phone (for the Fairphone 6: the
   first boot is `fastboot boot`, and `modemst*` is never written).
3. Run the checks:

   ```sh
   python3 -B tools/build-imager-catalog.py --check
   python3 -B -m unittest tests.unit.test_imager_catalog
   python3 -B tools/check-devices.py
   ```

## Adding an add-on

Add `imager/mods/<id>.toml` with `name`, `summary`, `arch`, `status`, `kind`,
and optional `note` and `[suggest_when]`. Leave it `coming_soon` until the
channel or installer it names exists.

## Building and publishing

```sh
python3 -B tools/build-imager-catalog.py --output catalog.json
```

Nightly: after `scripts/os/nightly-media.sh` has signed and published the
night's `media/<channel>/latest.json`, the publisher runs the generator from
the same checkout (so the ARM status reflects that night's index), refuses to
continue on a non-zero exit, and signs `catalog.json` exactly as
`nightly-media.sh` signs the media index: in `luma_os_tools` with
`$LUMA_OS_KEYS/update-graph-minisign` mounted, the password on stdin from
`$LUMA_OS_SECRETS/update-graph-minisign.password`, `minisign -S` with the
trusted comment `luma-imager-catalog schema=1 generated_utc=<generated_utc>`,
then `minisign -V` against `luma-update-graph.pub`. It uploads
`catalog.json.minisig` and then `catalog.json` to the `luma-images` R2 bucket
under `imager/v1/` (`application/json` and `text/plain`, `cache-control:
no-store`) and reads both back over `https://media.simplyluma.com`. A failure
leaves yesterday's signed catalog in place; it never blocks the nightly.
